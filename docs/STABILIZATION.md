## 점검했고 이상 없던 것

- **라우팅/오류 처리**: 미지의 경로 404, 잘못된 입력(빈 바디·깨진 JSON·필수 누락·
  숫자 자리 문자)에 400, 정상/특이값(음수·초대형)에 200. `/api/precise` 없는 id·id
  누락에 400.
- **HTML 구조**: 미닫힘/불일치 태그 없음.
- **회귀**: 단위 테스트 48건 통과. demo/validate 부가 도구 정상.
- **정밀 진단 종단**: 다운로드 → 형식감지(PDF/HWPX/HWP) → 파싱 → 요건 병합 → 판정.
- **외부 의존**: 페이지가 로드하는 외부 리소스 없음(폰트 시스템, CDN 없음).
  런타임 네트워크 요청은 `/api/*` 자체 엔드포인트뿐.

## 알려진 한계 / 의도적으로 바꾸지 않은 것

규칙상 "반드시 필요한 경우가 아니면" 대규모 변경·신규 의존성은 피했다.

- **음수 입력 서버 수용**: 프론트가 `min=0` 으로 막고 있어 실사용 흐름엔 영향 없음.
  서버측 방어 clamp 는 추후 하드닝 항목.
- **업종 매칭이 문자열 기반**: KSIC 표준분류 코드가 아니라 정밀도 한계(예: "제조"와
  "제조업"). 정성·정책 카테고리("대구 5대 신산업")는 매칭 대상에서 제외(오탐 방지).
- **파서 재파싱 비용**: 매 `/api/match` 마다 전 공고 자격요건을 재파싱. 현 규모(수십~수백
  건)에선 무시할 수준. 대규모 시 캐싱 필요.
- **다운로드 동시성**: 같은 공고문 동시 요청 시 중복 다운로드 가능(결과는 안전). 무해.

## 검증 제약

- 이 작업 환경(샌드박스)에서 헤드리스 Chromium 스크린샷이 불안정해, UI는 코드/DOM
  구조·서빙 응답·레이아웃 수치 계측으로 검증했다. 실제 화면은 로컬 PC에서 확인 권장.
- 실 API(기업마당·data.go.kr)는 샌드박스 아웃바운드가 차단되어 로컬 PC에서만 검증됨.

## 개선 의견 (미구현 — 규칙 11에 따라 목록만)

소비자 관점에서 유용하나 이번 범위(안정화) 밖이라 구현하지 않음:

1. 프로필/진단 결과 저장 및 재방문 시 불러오기 (개인정보 동의 설계 선행 필요).
2. 상위 적합 후보에 정밀 진단 자동 적용(다운로드 소요 시간 UX 설계 필요).
3. 마감 임박 공고 알림(이메일/푸시).
4. 업종을 KSIC 표준분류 코드 기반으로 매칭.
5. 기초지자체 자체 공고 수집기(현재 미수집 영역).
6. 폼 라벨-입력 for/id 연결로 접근성 강화(현재 시각 라벨은 인접 배치).
7. 다운로드 서버측 방어 clamp(음수/과대 입력) 하드닝.
